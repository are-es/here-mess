# here-mess

Fork of Hermes Agent (`are-es/here-mess`). This file is injected into every
system prompt, so it holds ONLY what must be known before acting. Everything
else is read on demand.

## Must know before acting

- Tests: `HERMES_PYTHON=/mnt/hdd/venv/bin/python scripts/run_tests.sh <path> -q`
  Never bare `pytest`. The in-tree `.venv` has no pytest — without
  `HERMES_PYTHON` the runner aborts.
- Fast syntax gate: `python3 -m py_compile <file>.py`
- TS: `cd ui-tui && npm run typecheck`
- Never `pip install` globally.

## Hard rules

1. Prompt caching is sacred — never mutate past context, swap toolsets, or
   rebuild the system prompt mid-conversation.
2. Use `get_hermes_home()` / `display_hermes_home()` from `hermes_constants`.
   Never hardcode `~/.hermes` — it breaks profiles.
3. `.env` is credentials only. Behavioral settings go in `config.yaml`.
4. No `git commit` / `git push` without explicit user approval.
5. Tests assert behavior and invariants — never read source text, never
   snapshot data that is expected to change.
6. Plugins never modify core files.

## Read on demand

- Project decisions, architecture, fork-specific state, pitfalls:
  `read_file('.ares/memory.md')`
- Upstream Hermes detail (~1500 lines, deliberately not injected):
  `search_files(pattern='^## ', path='AGENTS.md')` for the TOC, then
  `read_file('AGENTS.md', offset=<line>, limit=80)` for just that section.
